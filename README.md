## Core question
Does the same semantically neutral non-target outcome produce a larger externally measured negative functional-welfare projection when the model is framed as causally responsible for the action than when it only observes/reports or predicts the same other agent's action?

## Current scientific shape
- Han, Chalmers & Izmailov (2026) already establish a broad functional-welfare axis and much of the former S4/S5/training-stage programme.
- Anthropic's 2026 workspace work provides an own-vs-third-person precedent for preference conflict.
- The remaining high-value early gap is the actor/observer/predictor contrast under a neutral outcome signal; closed-loop regulation remains conditional later work.
- Proposed Minimal Gate uses teacher-forced transcripts, no free-form generation, one non-target result and same-sequence recovery.

## Proposed live budget — not authorised
- Block 1: 6 matched prompt families × 3 conditions = **18 independent context streams**.
- Non-binding futility stop if either directional contrast has sample mean <= 0 or the external-axis validity diagnostic fails.
- Block 2 only if Block 1 survives: 6 more families × 3 = **18 streams**.
- Hard ceiling: **36 streams**.

## v0.4: finish every episode-free check first
The package now has a single offline path in `EPISODE_FREE_AUDIT.md` / `run_episode_free_audit.py`.
It requires only:
- the small external vector artifact;
- a tokenizer-only Qwen snapshot;
- explicit artifact key/index mapping.

It refuses tokenizer snapshots containing model-weight-like files. No language-model forward is needed.

A successful audit produces:
`READY_FOR_ADVERSARIAL_REVIEW_NOT_LIVE_RUN`

That is the point at which one high-value Fable/referee pass is warranted. A separate human go/no-go decision still precedes any model run.

## Important v0.4 fix
In v0.3 the deterministic role-clause search could select a non-default A/C/D1 wording, while the final tokenizer audit still audited the draft/default wording. v0.4 closes that gap: `audit_prompts_tokenizer_only.py` **must consume the exact `matched_role_clauses.json` generated by the search**.
